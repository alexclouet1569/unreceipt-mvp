## Open problem (start here)

After `git pull` on `main`, `npm ci` and `npm run ios:sync`, the Xcode build fails with:

```
/Users/alexandreclouet/unreceipt-mvp/ios/App/App.xcodeproj Missing package product 'splash-screen_CapacitorSplashScreen.CapacitorSplashScreen'
```

**Already tried, still failing:**
1. Quit Xcode.
2. `npm run ios:sync`.
3. `rm -rf ~/Library/Developer/Xcode/DerivedData/App-*`.
4. Reopen Xcode.

Not yet confirmed: File → Packages → Reset Package Caches.

**Facts:**
- The very first build (#103, same `Package.swift`) worked.
- `ios/App/CapApp-SPM/Package.swift` is generated by `cap sync`. It pins `capacitor-swift-pm` `exact: "8.5.3"` and declares the plugin as `.package(name: "CapacitorSplashScreen", path: "../../../node_modules/@capacitor/splash-screen")`.
- The plugin's own `Package.swift` needs `capacitor-swift-pm` `from: "8.0.0"`, so the versions are compatible.
- Prefix `splash-screen_` = Xcode's package identity taken from the folder name.

**Next diagnostic step:** get the real resolver error. On the Mac, in the repo:

```bash
cd ios/App/CapApp-SPM && swift package resolve; cd ../../..
```

```bash
xcodebuild -resolvePackageDependencies -project ios/App/App.xcodeproj -scheme App 2>&1 | tail -40
```

**Hypotheses to check, in order:**
1. `node_modules/@capacitor/splash-screen` is missing or incomplete (`ls node_modules/@capacitor/splash-screen/Package.swift`).
2. GitHub fetch of `capacitor-swift-pm` failed: network, or a stale `~/Library/Caches/org.swift.swiftpm`.
3. Xcode 27's SwiftPM rejects `.package(name:path:)` when `name` ≠ folder identity. If so, check the Capacitor 8.x release notes or issues for a fix (a newer `@capacitor/cli` that writes `Package.swift` differently). Don't edit the generated file by hand: `cap sync` overwrites it.
